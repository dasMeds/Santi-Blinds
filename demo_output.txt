  5. RANDOMISED ENCRYPTION - identical values do not look identical
══════════════════════════════════════════════════════════════════════════════
  encrypt('0917 123 4567') #1: ENC1.k1.XioXA0+jVkfMgCRojZUMmncbRL0ejPOUdSkTCGoHxDcaoQY+3gLH…
  encrypt('0917 123 4567') #2: ENC1.k1.hPLcaUXH4pqdHlMn8wm+ZVxwY5332pTz6z5bgvE5fX0v/POg6wyo…
  Same ciphertext? False   Both decrypt to the same phone? True
  -> an attacker cannot tell which customers share a phone/city, nor spot repeated values.

══════════════════════════════════════════════════════════════════════════════
  6. BLIND INDEX - looking up a customer (login) without decrypting the table
══════════════════════════════════════════════════════════════════════════════
  Login lookup for '  Maria.Santos@Example.com ' (case/space-insensitive) -> customer id 1
  Same e-mail indexed with a different key -> f684ca9e498641e52da21928… (no match)
  -> only someone holding the key can compute the index, so e-mails cannot be guessed offline.

══════════════════════════════════════════════════════════════════════════════
  7. INTEGRITY - tampering is detected (GCM authentication tag)
══════════════════════════════════════════════════════════════════════════════
  Flipped ONE bit of the stored phone ciphertext -> decryption REFUSED (InvalidTag)

══════════════════════════════════════════════════════════════════════════════
  8. CONTEXT BINDING - ciphertext cannot be moved to another column
══════════════════════════════════════════════════════════════════════════════
  phone ciphertext pasted into the e-mail column -> decryption REFUSED
  -> stops an attacker with write access from swapping values between rows/columns.

══════════════════════════════════════════════════════════════════════════════
  9. WRONG KEY - the stolen database alone is useless
══════════════════════════════════════════════════════════════════════════════
  Attacker guesses/generates another key -> decryption REFUSED (no partial plaintext)
